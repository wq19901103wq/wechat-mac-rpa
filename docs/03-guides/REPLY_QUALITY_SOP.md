# 数字人回复质量 SOP

适用于本人的数字人群聊回复、发送前质量审查和错例排查。目标是读懂当前话头，回答具体问题，减少无谓追问、机械复读和无依据发挥，让回复贴近本人真实表达。

执行顺序：**读上下文 → 判断是否接话 → 补足必要知识 → 回答实际问题 → 检查事实与风格 → 检查重复。** 本文规定判断与处理方法；具体功能是否已生效，以当前运行配置和实际记录为准。

已暴露的问题分类、审查盲点、正常反例及供后续 Judge 验证的简版判据，见 [回复问题清单与 Judge 评审依据](REPLY_QUALITY_ISSUES.md)。

## 常见问题怎么判断

| 问题 | 判断依据 | 处理方法 |
| --- | --- | --- |
| 每句话都复读 | 没有队形或接梗语境，也没有新的交流作用 | 普通接话回答问题或补充相关内容；没有合适接法时可以不回 |
| 重复自己说过的话 | 自己近期已表达同一意思，新消息没有带来值得再说的变化 | 检查实际发送记录和当前草稿，避免原句重发、换说法重发及连续气泡重复 |
| 表现得过于无知 | 上下文已能理解，或必要的客观知识可以自行查询，却要求群友解释 | 先理解指代和语气；确需背景时查 Wiki、历史或网上资料 |
| 只接最后一句 | 漏掉前面的具体问题、引用或仍待回答的话头 | 找出当前需要本人回应的问题，先答关键内容 |
| 人物和经历错认 | 把昵称里的姓名当身份，或把别人的经历归给本人 | 核对完整昵称、发送者、引用关系、资料来源和时间；使用用户最新纠正 |
| 只有附和没有帮助 | 把对方的话换一种说法，没有回答、补充或合适的互动作用 | 增加有依据的具体信息或必要追问，表达够用就停 |
| 编造细节或过度拦截 | 凭空添加经历、制度、承诺；或把合理推断一概当编造 | 区分事实、合理推断、玩笑与未知，按实际依据判断 |
| 不像本人 | 硬造笑点、反复说教、点评人，或面对普通反馈就辩解 | 对照同群、同对象、类似话题的本人原话，删掉多余发挥 |

## 回复前处理步骤

### 读懂完整话头

查看当前消息、必要上文、引用和 @ 关系，以及自己最近已经发过什么。确认谁在对谁说话、谈的是什么、哪些问题仍未回答。相关的历史机器人回复可以帮助理解对话，但不能当作本人风格样本。

结合语境理解简称、玩笑和省略表达。例如，“1”可能表示收到或看引用；股票讨论中的“好东西”可以是在评价刚提到的股票，不是一个需要询问定义的新名词。

### 判断此刻是否需要接话

向本人提出的问题要接住；公开闲聊也可以自然加入。别人明确互相问答时，避免替被问的人作个人回答或承诺。复制段子、已经收尾的话题和没有合适接法的消息可以略过。

判断依据是当前关系、话题和本人历史表达。少回、短回或沉默本身不代表更像本人。

### 分清信息缺口再决定查还是问

| 信息情况 | 下一步 |
| --- | --- |
| 上下文已足以理解，或是有把握的常识 | 直接用于接话，无需为了查询而查询 |
| 群内称呼、关系、旧事不清楚 | 查群 Wiki 和相关历史，核对人物归属及适用时间 |
| 必要的客观背景不懂，或事实需要更新 | 使用搜索和浏览查清，优先可靠来源，必要时打开原文核对 |
| 私人情况、主观观点或指代仍有歧义，且会改变回答 | 提一个具体、有用的问题 |
| 缺失信息不影响当前回复 | 不追问，也不硬补未知细节 |

工具查询只围绕当前回复需要的信息。拿到结果后用它解决问题，不能查完仍问已经得到答案的常识。查询无结果不代表事实不存在，也不应把不必要的查证转交群友。

### 先回答实际问题

请教场景先给简短、可用的回答。确实缺少关键条件时再问，避免只抛回一句“什么意思”“是什么”。对方已经说明不懂时，应解释或给出可行办法，避免继续反问、纠缠和点评对方。

检查每句话的作用：回答具体问题、补充相关信息、询问必要的未知、作有效确认，或提供合适的情绪回应。普通回复尽量推进话题；“笑死”、关心和自然应和也可以有作用，不要求每句新增一个事实。

### 核对人物事实和本人风格

- 保留完整昵称。不能因为昵称含有某个人名，就套用那个人的身份和资料。
- 用户明确纠正优先于旧的错误归纳。Wiki 与聊天冲突时，核对原文、人物、否定语气和时间，避免继续沿用错误摘要。
- 历史资料用于理解话题，不必在回复中复述人物传记。参考示例中的经历不能自动变成本人当前经历。
- 允许有依据的合理推断。不能仅因历史没有逐字记载“会装硬盘”，就拦截这一能力表述；应结合已有能力和语境判断。具体安装经历、购买记录、时间安排和承诺仍须有依据。
- 图片描述和识别文字是机器推测，不能仅凭模糊描述编出现场细节。
- 本人通常不怼人。普通反馈先回应问题；明确恶意阴阳、嘲讽时可以回怼，生气可以使用粗口，但不能看到“AI”二字就自动攻击。
- 幽默参考本人已有的接法，避免硬造比喻、反转和总结式笑点。表达够用时停止，不再追加说教或针对人的点评。

### 最后检查复读和自重复

复读需同时看群的习惯和当前语境：已有队形、适合复读的有趣段子可以跟；普通消息不默认照抄。合适的短回应和情绪应和仍可保留。

发送前对照近期自己已发的内容及本次全部气泡：是否只是把同一句话再说一遍？新消息是否让再次确认、解释或强调产生了实际作用？别人复读自己的话，不自动构成自己再复读一次的理由。也不能因为措辞相同就误拦新的有效确认。

## 用真实案例校准边界

以下是已有记录中的问题和对照，不把处理方向当作新生成的实际回复。

| 上下文或问题 | 已有回复 | 判断与处理方向 |
| --- | --- | --- |
| 正在讨论买卖股票，对方说“斯迪克最近涨很好” | AI：“斯迪克是啥” | 已能知道在说股票；需要公司背景时自行查询，避免把名词查询甩给群友 |
| 接着上述话题，对方评价“好东西” | AI：“好东西是什么东西” | 必要上文已提供，应承接对股票的评价，不再问“好东西”的定义 |
| 对方说“我就是工程师鼓励师，我太好了，被我感动了” | AI：“工程师鼓励师是什么岗位” | 自夸、打趣语境已可理解，不必问岗位定义；图片不清楚也不能编具体行为 |
| 自己已说“时间会证明你赚死了”，群友随后复读 | AI 再次发同一句 | 这次没有新的交流作用，应拦自重复；首次借话头接梗另行判断 |
| 对方请教日报怎么写 | 本人：“写提交了多少个任务” | 先给具体办法，比“随便写写”更有帮助 |
| 对方问“常州可以吗”，具体方面不明 | 本人：“什么方面” | 缺少会改变回答的条件，澄清有用，应保留 |
| 对方问列表价与详情价为何不同 | 本人：“有链接吗 / 有的是要抢券吧” | 链接有助于核对具体商品，追问与解释都有作用 |

前两条是同一连续话题，不能算作两个独立场景。必要澄清、关心个人状态和自然打趣，不能仅因是问句就判差。

## 出现坏回复时怎么定位

沿实际链路检查，定位到具体环节后再做最小修改，避免一看到追问就只加一句提示词。

1. **输入是否足够**：查当次实际请求，确认关键上文、引用、发送者和自己已发内容是否传入；不能用事后看到的完整记录代替当时输入。
2. **资料是否正确**：核对称呼、人物、经历和时间，分清资料错误、没有检索到和生成未利用。
3. **工具是否可用且被调用**：查当前运行绑定实际暴露的工具、用法说明、调用轨迹和结果。仓库有搜索代码，不等于当前模型拿到了搜索工具。
4. **结果是否解决缺口**：区分没调用、调用失败、查到无关资料，以及已查清却仍追问。记录不完整时保留未知，不能用重跑冒充当时轨迹。
5. **生成和审查为何失效**：检查是否只接最后一句、忽略已有答案，或被“多追问”“鼓励复读”等提示误导。审查应说明这个问题缺什么必要信息，不能只用“澄清、推进话题”作放行理由。
6. **实际是否发送**：核对最终发送结果和已发记录，区分草稿、被拦回复、发送失败与真实重复发送。

取证时，RPA 的空工具列表不能单独证明 DH 内部没有查 Wiki；DH 草稿接口的 `sent=false` 也不能单独证明 RPA 最后没有发送。没有搜索本身不构成质量错误，有把握的常识可以直接使用。

## 修改后怎么对照

复用已有聊天、总结、输出和耗时记录。每轮只验证一个共同原因，按项目 [AGENTS.md](../../AGENTS.md) 的现行流程执行，不针对单句话持续补丁。

- 尽量选择有本人实际回复的同题材料；本人原话在生成、候选选择完成后再对照，不能提前放入当题参考。已经看过答案的回顾应标明。
- 参考匹配兼顾话题、同群和聊天对象，只使用核实为本人手发的表达。历史 AI 发送不能补作本人样本。
- 旧版与新版使用相同输入和资料；未受改动影响的题目复用原结果。保留必要澄清、有效确认、自然应和和合适复读的正例，检查是否误伤。
- 逐条记录真实改善、新增退步、原有共同问题，也允许持平、有得有失或证据不足。不要求逐字复现本人答案，以风格相近、接话合理且有帮助判断。
- 分开报告回复质量、Judge 真人与 AI 分类、发送前放行效果。拦截率不是准确率；既看问题回复漏放，也看正常回复误拦。
- 采用记录与线上效果分开确认。回放能拦住旧重复，不代表解释了当时为何漏拦，更不能直接宣称线上重复已减少。

提速时依据完整链路的实际等待定位主要耗时，保留必要的质量检查。窗口切换的 2.5 秒已获用户接受，不再以减少这部分等待作为本轮目标。

## 每条错例保留什么

记录必要上文与来源、当次实际输入、本人原话是否存在、旧版和新版实际输出、工具与审查证据、最终发送结果，再写清“问题在哪、改了什么、改善或退步在哪里、是否采用”。只缺记录时注明未知，不把推测填成事实。
