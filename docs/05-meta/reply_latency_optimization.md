## 瓶颈分析

### 瓶颈 1：绿色气泡检测 `_detect_self_bubbles`（11.7s，42.4%）

**根因**：
```python
diff = np.abs(arr.astype(int) - target)  # arr: 1760×1280×3
mask = np.all(diff < tolerance, axis=2)   # tolerance=35，mask 非常密集
labeled, num = ndimage.label(mask)        # 全图连通区域标记
```

- 对 **1760×1280** 全图做颜色容差 35 的像素级扫描
- 绿色气泡只占右侧消息区一小部分，但代码扫描了整张截图
- `ndimage.label` 在密集 mask 上运行缓慢

**浪费点**：
- 扫描了左侧聊天列表（绿色区域只有微信图标，不是消息气泡）
- 扫描了标题栏、输入框、时间戳等不可能有气泡的区域
- 容差 35 太宽，匹配了太多非气泡绿色像素（如头像、背景渐变）

### 瓶颈 2：LLM 网络请求（10.35s，37.5%）

**根因**：
- kimi-for-coding 是推理模型，每次请求需要完整思考链
- 网络往返 + 模型生成耗时

**浪费点**：
- 每次 tick 只有一个用户消息，但系统提示词每次都重新传输
- 没有流式响应，必须等完整内容返回才能发送
- 模型回复有时超过 50 字限制，需要截断或重新生成

## 优化方案

### ✅ 优化 1：绿色气泡检测区域裁剪（已实施，节省 ~9.3s）

**优化前**：
```python
# 扫描全图 1760×1280
diff = np.abs(arr.astype(int) - target)
mask = np.all(diff < tolerance, axis=2)  # 2.25M 像素
labeled, num = ndimage.label(mask)
```

**优化后** (`layout_parser.py:_detect_self_bubbles`)：
```python
# 1. 裁剪到右侧消息区（~0.5M 像素）
msg_region = arr[title_y_max:input_y_min, left_boundary:width, :]

# 2. 粗筛——高置信度绿色像素（容差 15）
strict_mask = np.all(diff < 15, axis=2)

# 3. 在稀疏 mask 上做 label（快 5-10 倍）
labeled, num = ndimage.label(strict_mask)
```

**实际收益**：11.7s → 2.4s，**提升 4.8 倍**

### 优化 2：LLM 流式响应 + 异步（预计节省 ~3-5s）

**当前代码**：
```python
resp = client.chat.completions.create(...)  # 同步阻塞
content = resp.choices[0].message.content
```

**优化后**：
```python
# 1. 使用流式响应，首 token 到达立即开始输入（typing 效果）
# 2. 或：异步发送，不等 LLM 返回直接结束 tick
# 3. 缓存系统提示词，减少每次传输
```

**预期收益**：用户感知延迟从 10s 降至 **5-7s**

### 优化 3：截图与 OCR 并行（预计节省 ~0.5s）

**当前代码**：
```python
capture.capture()   # 0.3s
ocr.recognize(...)  # 1.0s（串行）
```

**优化后**：
```python
# 使用线程池，截图完成后立即启动下一轮 OCR
# 或：Vision API 支持直接传入截图数据，减少磁盘 IO
```

**预期收益**：总感知时间从 13.5s 降至 **12-13s**
