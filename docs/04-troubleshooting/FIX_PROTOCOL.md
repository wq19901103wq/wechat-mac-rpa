# 修复协议（Fix Protocol）

> 强制执行的修复流程，防止"修 A 坏 B"、"把设计特性当 bug 修"、"顺手多改一行引入副作用"。
>
> **违反此协议的修复一律回滚。**

---

## 一、修复前（违反任一条 = 违规修复，必须回滚）

### 1.1 确认原有设计意图

- [ ] **看到"异常"代码，先假设它是设计特性，不是 bug**
- [ ] **查注释、spec、git history、troubleshooting 文档，确认原始意图**
- [ ] **不确定就问用户，禁止猜测**
- ❌ **禁止**：看到表面症状就当成根因，直接上手改。违者 = 违规

### 1.2 区分"症状"和"根因"

| 反模式 | 正解 |
|--------|------|
| 症状：messages=0 → 根因：本地路径不提取消息 ❌ | 症状：messages=0 → 根因：message_region 截断了底部导致检测不到变化 ✅ |
| 症状：paste 验证失败 → 根因：验证逻辑太严格 ❌ | 症状：paste 验证失败 → 根因：窗口焦点丢失导致内容发到其他应用 ✅ |

**原则**：修复必须指向根因，不能只消除症状。

### 1.3 汇报方案并获得确认

**以下改动必须先汇报，等用户回复"批准"后才能动手。提前动手 = 违规，必须回滚。**
- 改变模块的输入输出契约
- 新增/删除日志格式、配置项、环境变量
- 修改阈值、超时、重试次数等"魔法数字"
- 改动稳定运行超过 1 周的模块

**汇报格式（缺一不可）**：
```
问题：[一句话描述]
根因：[定位结果]
方案：[具体改动点，精确到文件和行号]
风险：[可能引入的副作用]
验证计划：[如何确认修复成功 + 如何确认没破坏其他功能]
```

**用户批准前，只能做这些**：
- 继续收集证据、看日志、跑验证脚本
- 写测试用例（先让测试失败）
- 讨论方案和权衡

---

## 二、修复中（用户说"批准"后才开始。提前动手 = 违规）

### 2.1 一修一改

- [ ] **一次提交只解决一个问题**
- [ ] **禁止"顺便优化""顺手重构"**
- [ ] **如果发现问题 B，先记录 B，修复 A 后再处理 B**

### 2.2 不改设计契约

- [ ] **模块契约 = 法律，修改契约必须同步更新 spec 和调用方**
- [ ] **禁止在接口不变的情况下，偷偷改变内部行为边界**
- ❌ **违者 = 违规，必须回滚**

### 2.3 最小改动

- [ ] **只改与根因直接相关的行**
- [ ] **不改注释格式、变量命名、日志 emoji**
- [ ] **不删除"看着像死代码"的代码**

---

## 三、修复后（必须验证，否则不算完成）

### 3.1 功能验证（不验证 = 不算完成）

- [ ] 修复的场景必须复现并验证通过
- [ ] 如果可能，写一个自动化测试，**先让它失败，再让它通过**

### 3.2 副作用验证（强制，不做 = 不算完成）

| 改动模块 | 必须验证的副作用 |
|----------|-----------------|
| **感知层** | 抽 1 个 tick 的 prompt，检查上文是否混入垃圾 |
| **发送层** | 检查 `[Sender] verify` 日志中的 raw_repr |
| **回复生成** | 检查 prompt 是否混入无关记忆、泄露隐私 |
| **日志系统** | 检查其他模块的日志输出是否正常 |
| **配置/阈值** | 检查边界场景（空输入、超长文本、特殊字符） |

**不做副作用验证就宣称完成 = 违规**

### 3.3 回归验证

- [ ] 运行现有测试套件，确保没有引入新的失败
- [ ] 如果修改了稳定模块，至少跑一轮完整的 tick 流程

## 四、本次事故复盘（2026-05-16）

### 事故：本地 OCR 垃圾混入 prompt

**症状**：Bot 回复混乱，prompt 中出现 "05/06"、"1000"、"i0i0" 等无关内容。

**错误修复**：
1. 误把 `_run_local_only` 返回 `messages=[]` 当成 bug，添加了 `_extract_local_messages` 强制输出消息
2. 本地 OCR 的 `message_candidates` 包含聊天列表日期、数字碎片、图标文字，全部进了 session 历史

**正确修复**：
- 只扩大 `message_region`（y2 从 0.85 → 0.97），让底部新消息能被像素差异检测到
- 本地路径保持返回 `messages=[]`，由 API 路径负责提取准确消息

**违反的协议条款**：1.1（未确认设计意图）、1.2（症状当根因）、2.2（偷偷改变本地路径的契约）、3.2（未验证 prompt 副作用）
